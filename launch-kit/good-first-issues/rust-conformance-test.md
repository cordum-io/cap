# [Good First Issue] Add conformance fixture decoding to Rust SDK

## Area
Rust SDK, conformance testing

## Context
CAP uses binary conformance fixtures (generated by `tools/conformance/generate_fixtures.go`) to ensure all SDKs decode protocol messages identically. The Go, Python, and Node SDKs already have conformance tests that decode these fixtures and verify field values. The Rust SDK (`sdk/rust/`) has a `testing.rs` module but does not yet include conformance fixture decoding.

Adding this ensures the Rust SDK stays wire-compatible with all other SDKs.

## What to Do
1. Look at how an existing SDK runs conformance tests — start with `sdk/go/` or `sdk/python/` test files that reference fixtures
2. Find the binary fixture files in `tools/conformance/` (generated by `generate_fixtures.go`)
3. In `sdk/rust/src/testing.rs` (or a new `sdk/rust/tests/conformance.rs`), write tests that:
   - Load each binary fixture file
   - Decode it using the Rust protobuf types (BusPacket, JobRequest, etc.)
   - Assert key fields match expected values (check the Go tests for reference values)
4. Run `cargo test` in `sdk/rust/` to verify all tests pass

## Files to Look At
- `sdk/rust/src/testing.rs` — existing test helpers
- `sdk/rust/src/codec.rs` — protobuf encoding/decoding
- `tools/conformance/generate_fixtures.go` — fixture generator
- `sdk/go/` test files — reference conformance assertions

## Definition of Done
- [ ] At least 3 conformance fixtures decoded and verified in Rust tests
- [ ] `cargo test` passes in `sdk/rust/`
- [ ] No changes to existing fixture files or other SDKs

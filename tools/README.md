# Tools

## Reproducible protobuf generation

`make_protos.sh` regenerates every checked-in protobuf surface with exact Buf,
remote-plugin, Node-plugin, and `grpcio-tools` versions. It never falls back to
host `protoc` and has no per-language skip flags. Install the exact Python
generator environment first with
`python -m pip install -r sdk/python/requirements-codegen.txt`.

```bash
# Generate twice in a clean temporary directory, prove idempotence, then use
# git diff --no-index to compare Go/C++/Node/Python/Ruby outputs with the repo.
./tools/make_protos.sh --check

# Run the same checks, then reconcile only known generated artifact files.
./tools/make_protos.sh --write
```

Both modes run `buf lint`, `buf build`, and `buf breaking` against
`origin/main`. Fetch that ref before running from a shallow clone. Go and Node
download caches may be reused, but the executable/plugin versions come from
`tools/proto_codegen.py`, `buf.gen.yaml`, and `tools/codegen/package-lock.json`.
Both checked-in Python trees are generated by the pinned bundled protoc in
`grpcio-tools`; this preserves the SDK's generated runtime-version guards.

Java and Rust generate protobuf code during their normal Maven/Cargo builds;
the proto-codegen CI workflow runs both build paths in addition to compiling
all checked-in generated-language surfaces.
